# 04: Browse authorized sources and resolve GitHub URLs

**What to build:** A signed-in user browses authorized repositories across installations and pages of mixed issues/PRs, or resolves a supported public issue/PR URL.

**Blocked by:** 01: Sign in through the GitHub App, 02: Arrange a reference-only native canvas

**Status:** ready-for-agent

**Work state:** done

## Acceptance criteria

- [x] Explain missing installation access and organization approval separately from sign-in; do not imply all accessible public URLs are installed sources.
- [x] Follow pagination including PR-only pages; preserve cursors, partial/loading/error states and explicitly local subset filtering.
- [x] Normalize issues and PRs without losing provider IDs, repository identity, record kind or same-number distinctions. Missing PR enrichment stays unknown, not confirmed unmerged.
- [x] Use only the relevant user token; validate external payloads and supported github.com URLs and construct requests rather than proxy arbitrary URLs.
- [x] Render bounded cards/list rows and full available detail without fetching bodies/comments merely for cards; keep authorized metadata outside documents.
- [x] Exercise controlled public HTTP provider behavior, partial pagination, malformed URLs, cross-user isolation, and private/public retrieval.

## Non-goals

No deployment-wide crawl, write permissions, fixture fallback, arbitrary hosts, or Projects permission until proven needed.

## Affected shared contracts

Own authorized item registry, metadata resolution and repository-source contracts; reuse authentication guard and current-user token lifecycle.
